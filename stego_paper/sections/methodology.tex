\section{Methodology}
\label{sec:methodology}

We propose a black-box linguistic steganographic method for public conversations.
The sender and receiver have accounts on a social media platform. Alice selects a post, writes a comment that appears to be an ordinary contribution, and publishes it. Bob reads the conversation and extracts the message from the comment's reply location and topic.
We use Reddit-style posts and comments. In principle, the idea can also apply to other platforms that allow comments on posts and replies to users' comments.

\subsection{System components, settings, and workflow}
\label{sec:method-setup}
The system consists of a social platform, a web-search service, a document-text retrieval tool, a helper language model, a writer language model, and encoding and decoding modules.
Google Custom Search API is one option for restricting searches to agreed sites.
The helper model generates search queries and extracts comment topics. Both parties need to construct the same lists from the same inputs, so they fix the model, its version, and the prompts, and set its generation parameter to
\[
\mathrm{temperature}=0.
\]
We call this the deterministic helper model to describe the intended reproducible configuration. This parameter alone cannot guarantee identical outputs if the input texts or model service change.
The writer produces comments through a black-box interface and may be a different, more capable model. A nonzero writing setting permits new wording on retries, while topic identification uses a separate fixed shared setting.

The system parameters fall into the following groups:
\begin{enumerate}
\item Conversation settings: platform, accounts, post-selection rule, and comment ordering.
\item Document settings: permitted search sources, query and result counts, text extraction, document ordering, and versions.
\item Topic-list settings: helper model, extraction prompt, topic count, ordering rule, and the fields in each topic record.
\item Encoding and writing settings: payload representation, allocation of bits to choices, writer model, comment length and style, acceptance criterion, and retry limit.
\item Publication settings: reply location, publishing account, publication time, and intervals between comments in a multi-comment transmission. The reply location carries part of the payload; publication rules and timing are agreed beforehand.
\item Decoding settings: shared-context reconstruction, topic identification, frame ordering, and message-integrity checks.
\end{enumerate}

Transmission proceeds through the following stages, explained below:
\begin{enumerate}
\item Select the post and prepare a copy of its comments for both parties to use.
\item Generate search queries, collect domain documents, and build the source-text list.
\item Map the source texts to an ordered comment-topic list.
\item Prepare the payload and select the reply location and topic from its bits.
\item Write and verify the comment, then publish it at the agreed time.
\item Reconstruct the lists at the receiver, identify the choices, and extract the message bits.
\end{enumerate}
The conversation changes while the sender works: new comments may arrive before research and writing finish. Both parties therefore need a common copy of the post's comments. Section~\ref{sec:waiting} explains how they define that copy after we describe the materials used to build the lists.

\subsection{Building the documents and comment-topic list}
\label{sec:search_determinism}
Alice needs material about the post's subject to support suitable replies. Bob needs the same material to reconstruct the topic list and interpret the selected topic index consistently.
We first explain the public-document principle in OPPRESSION~\cite{zillien2024oppression}, then describe our adaptation for collecting conversation and research texts and turning them into comment topics.

\paragraph{Public documents in OPPRESSION.}
OPPRESSION~\cite{zillien2024oppression} reduces the information sent through a communication channel by using texts already available on the Internet.
The parties agree on public documents, retrieve them, and build a codebook with a shared deterministic procedure. Instead of transmitting a long message fragment, the sender transmits a short pointer to a matching fragment in those materials.
They may agree on a website address, a predefined query returning a fixed set of articles or posts, or the latest article on a site at a specified time.
OPPRESSION~\cite{zillien2024oppression} handles representation and compression; it leaves embedding and extracting those pointers to another communication tool. It does not specify how to generate social-media comments.

The paper describes two pointer methods. The first treats each document as a sequence of words. A pointer
\[
P=(i,o,k)
\]
specifies document $i$, starting offset $o$, and word count $k$. The sender finds the longest matching fragment and continues with the remaining message.
The second extracts word sequences with a sliding window and combines them in a prefix tree. A node identifier represents the word path from the root to that node; the receiver reconstructs the fragment by reading the path.
The paper also describes spelling out words absent from the codebook. Such fallbacks are needed to preserve a complete message when the documents do not cover all its words.

Web documents can change or disappear, and search results can change even while the pages remain available. A publication timestamp does not necessarily identify a preserved version of the text.
OPPRESSION~\cite{zillien2024oppression} therefore describes a persistent mode using documents or versions that can be retrieved again, and an ephemeral mode using a document copy collected during an agreed interval.
Dated Wikipedia revisions suit the persistent mode; the latest articles at an agreed time can suit the ephemeral mode.
The paper notes that an old document set becoming unreconstructable may limit a monitor's ability to decode earlier messages, but requires the parties to build the appropriate codebook at the required time.
It also proposes comparing document hashes to detect changes. A hash detects a difference; it does not make different texts identical.

Our implementation is an initial simplified adaptation: it builds shared material from the post, its comments, and domain documents, then uses that material to extract comment topics and prepare a compression dictionary.
Model-generated search queries and reply-topic selection belong to our method, rather than to OPPRESSION~\cite{zillien2024oppression}.
Section~\ref{sec:compression} explains how the shared materials support text-payload compression.

\paragraph{Generating search queries and collecting domain documents.}
Queries can be derived from a domain description, the community's subject, or the post and comments.
Our implementation uses the post's title and body because they directly identify the issue addressed by the conversation.
The helper model receives one prompt requesting varied queries related to that context. It produces multiple queries, rather than twelve distinct prompts.
The configuration requests at least 12 unique queries, targets 15--20, and selects 8 according to a shared rule. These counts are adjustable settings, not essential requirements of the method.

The parties search the agreed sources with those queries and take the top 10 results per query.
Shared post-processing standardizes the extracted texts, removes duplicate material, and orders the documents consistently.
The agreement identifies document versions or preserved content copies where needed: the same query does not guarantee the same search results at different times.
Matching documents and their order are required alongside matching helper-model settings.

\paragraph{The source-text list.}
The texts we read are distinct from the comment topics extracted from them.
The source-text list combines three groups: the post title and body, a copy of the post's comments with their reply relationships, and the domain documents collected through search.
Each text retains its source reference so an extracted topic can be linked to the document or comment that inspired it.
The conversation keeps its reply structure even when its texts are represented as a list for processing.

Let $D=(d_1,\ldots,d_m)$ be the ordered source-text list and $\theta$ the shared extraction configuration.
The step $f_{\theta}$ extracts topics from each text. The step $R_{\theta}$ combines the outputs and applies the agreed ordering and count rules:
\[
\mathcal{A}=F_{\theta}(D)
=R_{\theta}\bigl(f_{\theta}(d_1)\Vert\cdots\Vert f_{\theta}(d_m)\bigr).
\]
Here $\Vert$ concatenates lists while retaining their order.
This is the intended deterministic mapping from texts to topics. Matching outputs require fixed texts, their order, the prompt, the model, and post-processing rules; searching the same domain is insufficient.
Selecting a reply location does not reorder the prepared post-level topic list.

\paragraph{The topic record and ordered list.}
We use the name \emph{comment-topic list} for the structure called \texttt{tangent DB} in implementation artifacts.
Each record contains a source quote, a description of the subject a comment could discuss, a category describing the idea, and a source reference.
The quote supplies inspiration and the topic description specifies the idea to express. The writer is not required to copy the quotation.
For example, a quote about high device-repair costs may inspire a comparison of repair with replacement.
Each record receives an index in the final ordering; payload bits select one of these indices.
The shared configuration sets the maximum number of comment topics, and both parties use the same value when building the list. The evaluation section specifies the limit used in each experiment.
\label{par:topic-count-choice}
This limit controls a tradeoff between the selection budget and reliable identification. Doubling the number of distinguishable topics adds one nominal bit, while additional similar topics can make the intended choice harder to identify. It also increases list-construction and matching work. The count is therefore a shared configuration choice, not a fixed requirement of the method; a larger list is useful only when its choices remain recoverable.
This topic list is separate from the compression dictionary, even when both use the same source texts.

\subsection{Preparing a copy of the post's comments}
\label{sec:waiting}
Collecting documents, extracting topics, and writing a comment take time while new comments continue to arrive.
If Bob reads the complete conversation after publication, he may include comments that Alice did not see when she began. These additions change the reply-location list and may change the texts used to extract topics.
The purpose is therefore to define a common copy of the comments.

The parties agree on an interval $T_{sync}$ between Alice collecting the comments and publishing her reply.
If she collects them at $t_{start}$ and publishes at $t_{publish}$, then
\[
t_{start}=t_{publish}-T_{sync}.
\]
Bob reads the carrier comment's publication time and retains comments available up to that cutoff. He excludes the carrier comment and its descendants.
The interval must accommodate research, preparation, writing, and verification: $T_{sync}>T_{process}$.
If processing finishes early, Alice waits for the agreed publication time. If it exceeds the interval, she cannot publish the result while assuming the old cutoff.

This procedure requires readable publication times and an agreed rule for comments exactly at the cutoff.
The cutoff identifies eligible comments but cannot reproduce text edited or deleted after Alice collected it. Preserved content or a versioned source is needed when such changes affect the lists.

\subsection{Selecting the reply location and comment topic}
\label{sec:layer1}
\label{sec:layer2}
Payload bits select one reply location and one comment topic. Figure~\ref{fig:two-layer} illustrates the two lists and their roles.
\begin{enumerate}
\item Both parties order the comments by a deterministic depth-first traversal of the reply tree. The list contains $C=n+1$ locations: index 0 means replying to the post, and indices $1$ through $n$ refer to comments. The first group of bits selects the reply location.
\item The next group selects a topic from the prepared list $\mathcal{A}$. The writer receives its description, source quote, and source reference, together with the post, the selected comment, and its parent chain.
\end{enumerate}
\label{sec:channel-widths}
Using independent power-of-two subsets of the lists gives a distinguishable selection budget of
\[
b=\lfloor\log_2 C\rfloor+\lfloor\log_2 A\rfloor,
\]
where $A$ is the topic count. Three reply locations and five topics, for example, provide $1+2=3$ distinguishable bits.
Layer~1 takes its bits from the start of the stream prepared in Section~\ref{sec:compression}, and Layer~2 takes the following bits.
The lossless writer uses the restricted choice sets so every choice can be inverted to its original bits.
Reducing an excessive index modulo the choice count can map two different bit patterns to the same choice and prevents independent extraction of those bits.
This is a distinguishable-choice budget, not Shannon capacity or useful payload size after control fields.
Payloads exceeding this budget require additional frames, as described in Section~\ref{sec:multiframe}.

\subsection{Writing the comment and verifying that Bob can read it}
The writer produces several short candidate replies from the context and selected topic. Its settings determine comment length, candidate count, and wording variation.
It receives the post, parent chain, selected topic, and a research excerpt. The topic guides the reply's content without appearing as a category label.
Before accepting a candidate, Alice uses the same topic-identification step as Bob, requiring a valid index.
A reply is accepted only if that step identifies the selected topic and the contextuality check passes.
Otherwise, the sender retries with the same reply location and topic until a candidate is accepted or the retry limit is reached. A near-miss may be revised before another check.
The current sender saves the result locally and does not publish it on Reddit.

\subsection{How the receiver extracts the bits}
Bob extracts Layer~1 from the visible reply location and its index in the depth-first ordering.
The Layer~2 topic index is not printed in the reply.
The reconstruction path identifies Alice's comment by account, removes it from the supplied post, and may repeat research and topic preparation. It then:
\begin{enumerate}
\item embeds the comment with \texttt{all-MiniLM-L6-v2} and retrieves a preliminary set of nearby topics from the shared list;
\item combines semantic similarity with lexical overlap to rerank that set and retain the candidates shown to the identification model; Section~\ref{sec:model-settings} explains the retrieval and prompt limits;
\item asks the stego model for a line \texttt{idx: N} containing the canonical topic index, using the separately recorded identification setting.
\end{enumerate}
If the model returns a shortlist rank instead, the program maps it to the original index. If no index can be parsed, it uses the nearest semantic candidate. Sender acceptance requires strict identification without these fallbacks.
Reconstruction using private sender records differs from independent receiver extraction. Section~\ref{sec:recovery-contract} specifies the inputs supplied in recovery experiments, and the evaluation chapter explains each experiment's limits.

\subsection{Preparing a text payload}
\label{sec:compression}
A text message can first undergo an optional protection transform and then compression against a session dictionary built from the post body, search texts, and ordered comment bodies, in that order.
The balanced profile defaults to \texttt{plain}, which leaves the payload unchanged.
The modes \texttt{hmac\_xor\_v1} and \texttt{secure\_compact\_v2} use a keyed stream cipher and a truncated MAC. The sender records the mode so Bob can apply the matching inverse.
These transforms protect the message contents; the publication method conceals the communication.

One compression representation starts with a mode bit and then uses either raw UTF-8 or literals and dictionary pointers.
The dictionary parse is selected only if shorter, so expansion is at most the mode bit.
Literal segmentation and reference-search limits are implementation choices described in Section~\ref{sec:implementation}.
The shared codec defines field widths and selection of the literal/pointer sequence; Section~\ref{sec:implementation} describes their layouts.
This compression dictionary is separate from the comment-topic list.
Another representation uses versioned prefix-tree nodes. The system chooses the shorter representation with its identifying fields and preserves Unicode, whitespace, and punctuation exactly.
Figure~\ref{fig:compression} illustrates payload preparation with a shared dictionary.
The representation fields form part of the bitstream consumed by the two layers. One comment transfers only the bits that fit its selection budget; the remaining bits require additional frames.
