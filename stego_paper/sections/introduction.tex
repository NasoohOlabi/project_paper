\section{Introduction}
\label{sec:introduction}

Linguistic steganography hides a secret inside ordinary text.
Early methods mostly swapped synonyms \cite{qiang2023natural}.
Natural language has little spare room, so even small statistical quirks can give a detector something to grab \cite{yang2020vae,kaptchuk2021meteor,Wang_2023}.
Large language models changed the cover: instead of editing an existing sentence, many systems now generate the text \cite{li2023rewriting,lin2024zero,wu2024generative}.
Those systems usually hide bits by steering next-token sampling, which can look fluent while still sitting on a modified distribution.

\subsection{Research motivation}

That fluency still has to fit the thread.
A model can write a grammatical, low-perplexity sentence that does not belong in the conversation \cite{liao2024co,wang2023hi,zhang2024controllable}.
A comment that is fluent but off-topic is conspicuous to a human reader and to a semantic checker \cite{olabi2026slr}.

In a discussion, readers interpret a comment together with the post and the comment to which it replies.
Conversational fit therefore depends on both what the comment says and where it appears.
This motivates a channel in which the reply location and the comment topic are part of the embedding decision, rather than evaluating the generated text in isolation.

Token-directed methods also assume access to the model's next-token probabilities.
An API that exposes only generated text provides no such distribution, so the payload needs another observable carrier.
Reply location and comment topic provide that carrier when both parties can reconstruct the same choices.

\subsection{Research problem}

The problem is to place message bits in choices that look ordinary in a public conversation and to identify those choices at the receiver without access to the model's token probabilities.
Writing a suitable comment is not enough: the parties must agree on the possible reply locations, candidate topics, and their ordering so that one choice denotes the same bits for both.

The conversation may change while a reply is being prepared, search results may differ, and the model may fail to identify the intended topic in its own output.
The design addresses these cases with an agreed operating window, hashes and data-integrity checks, and a sender-side verification step before publication.
The evaluation separates development checks of list reconstruction from experiments that embed and extract complete messages.

\subsection{Research objective and scope}

This paper describes a two-layer selection channel in a public discussion, states the coordination required by its sender and receiver, and evaluates accepted comments and message extraction under specified experimental conditions.
We assess the proposed improvements using explicit comparison criteria and explain the baseline choice and the differences that affect interpretation in Section~\ref{sec:baseline-choice}.
The paper does not provide a theoretical security proof, claim that a public conversation alone is sufficient for recovery in every setting, or establish general superiority against steganalysis.

We hide the payload in two conversational choices rather than in token probabilities.
Both parties build an ordered topic list from the post, its comments, and texts collected through search. They use the same topic-extraction and ordering rules so that each index refers to the same topic for both parties.
Bits select (i) which comment to reply to in a depth-first flattened thread, and (ii) which topic from that list the comment will discuss.
A language model then writes an ordinary visible reply for that pair.
We do not use invisible characters.
Before keeping the comment, the sender uses the same topic-identification step as the receiver and retries if it identifies the wrong topic.

\subsection{Research questions}
\label{sec:research-questions}
The following questions organize the method and evaluation, distinguishing what the design specifies from what the experiments measure:
\begin{enumerate}
    \item How do the reply-location and comment-topic lists carry bits, and what shared data and agreements let both parties reconstruct them?
    \item How successfully does the sender generate a comment expressing the selected topic, how successfully does the receiver extract the message from the resulting comments, and what causes failure at each stage?
    \item How do accepted comments compare with those of Zero-shot Generative Linguistic Steganography (ZLG)~\cite{lin2024zero} under the independent judge's criteria, and what conclusions does that comparison support?
\end{enumerate}

\subsection{Main contributions}
The primary contributions of this paper are:
\begin{itemize}
    \item A context-aware black-box linguistic steganography method in which reply-location and comment-topic choices carry message bits, and a language model writes a comment suited to those choices and the context. The method calls the model through an API for embedding and extraction without requiring its internal token probabilities.
    \item A sender--receiver coordination procedure that specifies shared texts, list-construction and ordering rules, and how both parties identify the comments they use as the conversation changes. This agreement lets both parties interpret the reply location and comment topic using the same indices.
    \item A closed-loop verification mechanism that simulates decoding before the comment is kept and retries synthesis, with an optional revision pass, under stochastic generation.
    \item An experimental evaluation covering comment quality, generation success, and message extraction. An independent language model compares our comments with ZLG~\cite{lin2024zero} comments on 244 posts, and a separate configuration comparison covers 304 comment pairs. We also report independent-receiver extraction experiments, specifying the shared data available to the receiver in each experiment.
\end{itemize}
